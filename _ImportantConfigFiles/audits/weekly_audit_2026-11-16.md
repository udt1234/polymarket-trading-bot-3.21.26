## CODE — `feat/newbot-step1-skeleton`

### CRITICAL
- **C1 — Correlated-exposure cap (30%) is effectively not enforced.** *(`@risk-auditor`, `api/services/risk_manager.py:110-133,215-218`)* When a signal carries a slug, `corr_key` is set to the auction slug, but positions are matched on `market_id == slug` — positions actually store `condition_id`, so this never matches. The code comment claiming "every bracket shares one condition_id" is wrong; discovery returns a distinct `conditionId` per bracket. Orders are matched via `metadata.auction_slug`, but no module writes that key. **Failure scenario:** a module stacks 5 mutually-exclusive brackets of the same auction at 14% each (70% of bankroll) — the correlated check sees only the new order each time, so only the blunter 50% portfolio cap would stop it.
- **C2 — Engine hardcodes a module name and reaches into that module's internals.** *(`@qa-architecture-quality`, `api/services/engine.py:201,251,255,261`)* `_active_sports_series()` does `from api.modules.sports_sweep import data as sports_data`, calls `self.registry.get("sports_sweep")`, filters `.eq("strategy","sports_sweep")`, and reads `cfg["series_ids"]` — a key only that module defines. This is the exact "hardcoded module name in engine/router code" pattern CLAUDE.md's Module Architecture Rules forbid. A generic `BaseModule.get_live_quotes(module_id)` hook (default `{}`) would let the engine loop over active modules instead.
- **C3 — The hot-path pre-signing lane has no risk gate at all.** *(`@qa-code-bug-hunter`, `api/services/hot_path.py:92-121`)* Between `build_ladder()` and `create_signed_post_only()/post_signed()` there is no call to `risk_manager.check()` anywhere — the code's own comment admits "NO per-order risk_manager.check() anywhere in the lane... does NOT enforce exposure/loss/duplicate/depth limits." **Currently this is dead code** (`HotPath`/`PreSignLoop` have zero call sites in `api/`), so it is not live-exploitable today, but per CLAUDE.md ("prefer deleting code over adding it") it should either be deleted until it's wired through the risk gate, or have `risk_manager.check()` added before it's ever turned on. **Do not wire this into the engine without `@risk-auditor` re-reviewing it.**

### HIGH
- **H1 — Module-budget cap fails open to the entire global bankroll.** *(`@risk-auditor`, `config_store.py:24-36`, used at `risk_manager.py:222-226`)* If a module's `budget` is `NULL`, the module row is missing, or the budget read throws (exception swallowed), the cap silently becomes 100% of global bankroll instead of that module's budget. **Failure scenario:** a module created without a budget set could consume the entire 50% portfolio cap — the same single-module monopolization an earlier 2026-07-22 fix was meant to prevent. This is the "wrong denominator" class of bug CLAUDE.md specifically calls out to watch for; it's not the exact dust-floor variant (that one's already fixed, see Verified below) but the same failure mode on a different cap.
- **H2 — The duplicate-order guard blocks the second leg of every pair-arb trade.** *(`@risk-auditor`, `risk_manager.py:197-203`; `arb_scanner/module.py:171-173`, `elon_late_arb/module.py:124-126`)* The guard keys on `(module, market, bracket, BUY)` and ignores `token_id`. Both legs of a YES/NO arb pair share the same market+bracket, so the YES leg rests and the NO leg is rejected as `duplicate_resting_order`. This directly matches the live-data finding (M-L2 above): `duplicate_resting_order` is the #1 historical rejection reason (51,820 rows), and `arb_scanner/module.py:48-49` itself notes a "$384 held 39 days" orphan position consistent with a stranded single-leg "arb."
- **H3 — No working regression tests for money-touching code; the suite is broadly API-stale.** Ran `pytest` on this branch: **9 failed, 3 collection errors, 70 passed.** `tests/test_risk_manager.py`, `tests/test_engine.py`, `tests/test_copy_trading.py` fail to even import (`RiskManager`, `TradingEngine`, `api.modules.copy_trading` don't exist under those names any more — matches `@qa-architecture-quality`'s finding independently). `tests/test_executor.py` has 7 failures, including mocks patching `api.services.executor.open_position` (doesn't exist) and `LiveExecutor(profile=...)` (no such kwarg any more). I spot-checked the two `tests/test_signals.py` failures by hand: both are stale-test bugs, not live bugs — `rank_brackets()`'s default `top_n=5` behaves correctly and the test simply forgot to pass `top_n=3`; `kelly_sizing()`'s documented 30%-floor time-decay is working as commented, the test expected full zero-out. **Net effect: the test suite currently verifies almost nothing about the live risk/execution path — a real regression in `risk_manager.py` or `executor.py` would very likely pass CI today.**

### MEDIUM
- **M1 — `is_exit=True` skips every risk check, including on a mis-flagged BUY; re-quoted SELLs have no duplicate guard.** *(`@risk-auditor`, `risk_manager.py:156-157`)* Breaker, halt, exposure, and depth are all bypassed for anything flagged as an exit. A module bug setting `is_exit=True` on a BUY would create a fully unchecked entry; market_maker's re-quoted SELLs (`market_maker/module.py:84-93`) stack every cycle with no size check against the actual position.
- **M2 — Arb-leg signals hardcode `spread=0.0`, bypassing the spread gate.** *(`@risk-auditor`, `arb_scanner/module.py:142`, `elon_late_arb/module.py:82`)* These price at the ask with post_only; live they'd be rejected on resubmission, but in paper mode they fill instantly, inflating paper arb P&L relative to what live execution would actually achieve.
