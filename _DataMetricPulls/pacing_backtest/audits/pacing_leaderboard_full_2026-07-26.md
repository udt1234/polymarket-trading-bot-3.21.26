## Findings

**[Class D] [LOW/advisory] Holdout split pre-registration cannot be proven from version control, but is confirmed robust by an independent sweep.**
pacing_leaderboard_full.py was never committed to git before this run (still untracked in git status), so there is no artifact proving the 70/30 split was fixed before the author saw results. Dynamic confirmation performed: re-scored SELECT/HOLDOUT at 8 split fractions (0.50 through 0.85) directly from pacing_leaderboard_full_records.csv. At every single fraction tested, both mae_holds and hit_holds came back False -- the in-sample winner never beat LOCKED on the untouched tail slice, regardless of exactly where the cut is placed. This rules out the concern that the 70/30 point was chosen because it produced a favorable null -- the null is split-invariant. Residual risk is only that the practice of pre-registering via a commit was not followed; the conclusion itself is not an artifact of the specific split chosen.
Fix: commit the split constant (or this script) before the next run of any leaderboard, so pre-registration is provable from git history, not just re-derivable after the fact.

**[Class D] [LOW] The MAE-side holdout reversal is statistically significant; the HIT-side reversal is not.**
Paired bootstrap-by-auction (n=20 holdout, 5000 resamples, seed 999):
- Inhomog. Poisson minus LOCKED, MAE: mean +12.20pp, 95% CI [3.12, 22.22] -- excludes zero, i.e. LOCKED significantly outperforms the in-sample MAE winner out of sample.
- Bursty Nowcast minus LOCKED, HIT%: mean -2.00pp, 95% CI [-7.00, +3.00] -- includes zero, i.e. the HIT-side underperformance of Bursty Nowcast vs LOCKED is not statistically distinguishable from a tie at n=20.
Net effect on the verdict: neither model is a proven improvement, but on HIT specifically the honest read is no significant difference, not LOCKED wins. This is a nuance, not a reversal of the recommendation.
